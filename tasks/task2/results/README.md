# Сервисы бронирования и статистики бронирований

Реализован сервис бронирования booking-service, который повотряет логику монолита и берет на себя эту функциональность. Также реализован сервис статистики бронирований booking-history-service, он совершенно новый.

В сервисе booking-service реализован и просмотр бронирований (сверх задания).

## Изменения в тестах

Доработка regress.sh включает:
- Данные для теста чтения бронирований заносятся в базу сервиса booking-service, фикстуры для новой базы перенесены в отдельный файл, поправлен Dockerfile для использования двух файлов фикстур.
- Отключен сбойный тест чтения всех бронирований, логика вызова сервиса по gRPC из монолита приводит к ошибке при запросе всех бронирований (p-o-y-1.0.0.jar).
- Добавлен тест чтения из базы сервиса booking-history-service исторических записей.

## Миграция данных при запуске нового сервиса

Новый сервис бронирования хранит данные в своей отдельной базе.
База сервиса должна взять на себя хранение бронирований полностью.
Поэтому нужна миграция данных из базы монолита в базу сервиса.

План (предполагает перерыв сервиса):

1) Приостановка приема бронирований в монолите (или остановка монолита)
2) Экспорт бронирований из базы монолита
3) Имопорт бронирований в базу сервиса
4) Перезапуск монолита с перенаправлением запросов в новый сервис
